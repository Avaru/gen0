# 0004: Interface and routes

Keep the app usable on 320px phones and current browsers. Use a phone single-column layout and a settings/results split when space allows, without horizontal page scrolling.

- Use semantic HTML, visible focus, readable contrast, explicit labels, 44px touch targets, and hidden status announcements. Aim for WCAG 2.2 AA; automated checks do not establish screen-reader or real-device accessibility.
- Shared `Ui*` components own scoped presentation. `UiSheetCard` owns sheet frames, headings, and rule typography; `UiSheetField` owns editable text fields and wrapping print values, including the shared Runner-style field and its label below. Shared controls own their hover and focus styles, with inherited variables for colored surfaces. Central CSS variables own repeated tokens; pages coordinate state with little CSS. Add VueUse only when native HTML, Vue, and Vue Router are insufficient.
- Flavor is a native radio group. Gender and size use checkboxes, all selected initially and always enabled; unchecking the last selected choice selects all the other choices. Each result picks equally among selected choices. Keep each person's name-part gender consistent.
- The picker uses `UiModal` for their native dialog frame, heading, Close button, initial Close focus, and keyboard focus wrapping. Categories use a searchable grouped native dialog: full-screen on phones, centered from 640px. Match all search words against category/group labels; Enter selects a single match. Close/Escape cancels, selection closes, and focus returns to the trigger. Focus Close on phones/touch devices and search on larger mouse-driven screens.
- Nationalities appear last, with Mixed first. Generic offers continent mixes; setting flavors offer sovereignty mixes immediately before nationalities. Missing pools remain visible as TODO with coverage notes.
- Generate 10 names initially and on setting changes. Scrolling down to the bottom appends 20 without moving the viewport. The manual button rerolls; no batch-size control or result counters.
- Manual generation reveals the first result only if needed. Category selection, automatic generation, and route restoration do not scroll. Respect reduced motion for scrolling, name reveals, and control transitions.
- Use `/:flavor/:category` and applicable `gender`/`size` queries. Accept comma-separated or repeated query values; discard duplicates/unsupported choices and default empty selections to all. Omit all-selected or irrelevant groups.
- Path settings take precedence over legacy query settings. Normalize root, incomplete, and invalid links with history replacement. Unavailable Known corporations falls back to Corporations; other unavailable categories fall back to Runners. Selection changes add history entries; reload and Back/Forward restore settings and generate fresh results.
- Results are temporary. Details visibility defaults on, survives navigation in app state, and resets on reload. It never regenerates names or enters shared links; remove old `count`/`details` queries.
- Generated text uses primary and secondary levels. Runner results show the archetype in the secondary row: bold Rajdhani in the signal color, larger than details but smaller than the name, visible even with details off. The character sheet's generated details field contains only real-life details and appearance, without the archetype. Other categories retain their existing display behavior.
- About uses `/:flavor/:category/about`, with `/about` also supported. Header links preserve settings and theme; returning generates a fresh batch. Top-menu navigation always scrolls to the top, including selecting the current page. Moving between pages focuses the main content without scrolling or an outline around the text block; initial loads and reloads do not move focus. Settings changes retain control focus. Header focus outlines contrast with the page background, and forced-colors mode exposes native radio/checkbox states. Its heading and text use the shared garbled reveal, respecting reduced motion. Show `v/{short commit hash}` in very small text above the right end of the header's striped separator, using the version supplied during the build.
- Map flavors reactively in `src/styles/themes/index.ts` and bind the theme on `UiShell`. CSS `:has()` applies document tokens. All three flavors share the yellow, near-black, cyan/coral appearance. Flavor changes affect generator content, not styling. Layout and controls stay shared; no theme picker or dark/light setting.
- `UiBrandTitle` owns the header title. Its colored layers flicker and shift sideways by up to 288px, allowed to extend beyond the viewport, in stepped bursts starting immediately, for 10 seconds, then stay at their resting offsets. Hovering over the title replays the animation once; remaining hovered does not loop it. The main text stays steady; reduced motion keeps the layers still.

- The CBR+PNK character sheet uses `/chars/cbrpnk`. The “CBR+PNK” header link always uses the plain path. The route fixes its flavor to Generic for the theme and all nested generation, even when a legacy link includes another flavor query. Returning through the header uses Generic; browser Back restores the earlier page normally. Category, gender, and size are not carried to the sheet. On the sheet, the header caption reads “CBR+PNK / Runner sheet” instead of “Cyberpunk name generator”; there is no duplicate sheet title. `UiCharacterSheet` presents catalogue approaches and skills with editable ratings, expertise, and glitch marks; `UiRatingChecks` provides two native + checkboxes, capped at 2. Selecting the right checks both; clearing the right leaves one, and clearing the left clears both. Approaches and Skills have visible headings and use the name generator’s shared workspace, panel styling, and row typography. The sheet uses only the Generic theme. The small expertise rule sits at the top beside Skills, right-aligned with the expertise choices. `UiHarmCard` follows the supplied three-level sheet with 2/2/1 independent slots and descriptions stored in Pinia. It sits below Approaches on desktop, after Skills on mobile; a full level 1 turns the card yellow, full level 2 or 3 red, with red taking priority. Pinia owns the sheet, preserving edits across navigation and saving them to local storage (`gen0.character`). Load usable saved sheet data once when the store starts; otherwise keep the blank defaults. Save edits automatically, without cross-tab synchronization. Batch text edits after a 200ms typing pause; checkbox changes, generation, and reset save after the current Vue update. Flush pending text when the page hides or the store is disposed. Saved sheets without runner fields keep their existing edits and start with blank runner fields. Ratings start blank (`null`), expertise selections empty, and Glitched toggles off. Approach and skill cards use dark/yellow/cyan for 0/1/2, with red overriding only an approach’s color when glitched. The hazard toggle sits next to the rating on desktop, below on smaller screens; a glitched card shows its negative name beside the original, in space reserved even when off, without shifting the layout or changing its rating. Colors reuse the shared palette, with yellow in `--color-rating-one`. Expertises are independent native checkbox choices from the supplied Skills card, stored as lists; each skill permits zero through all preset options. Choices use narrow uppercase text, broken underline accents, and top-left wrapping rather than boxed buttons. Selected choices use a textured yellow marker and a check mark regardless of the skill rating. At every screen width, skill ratings sit below the name on the left; expertises start directly alongside them and align with the bottom of the rating boxes. On desktop, the name spans the first row, with the rating boxes and expertises directly alongside each other in the second row, so longer names do not force extra lines. Each expertise choice and the custom field use the same control height as the rating boxes. Each skill has a Custom expertise text field filling the remaining space in the choices, styled as selected when filled and saved with the sheet. Blank or whitespace-only custom fields do not print; filled fields print as selected expertise text. Reset and archetype application clear custom expertise along with the preset selections. Attune is displayed as an optional Weird skill; the form does not perform rules validation. Generate applies the linked CBR+PNK profile’s Approaches, Skills, and expertise. A stored skill value of 3 means two rating points plus one randomly selected matching expertise; no third box is added. Existing source wording maps to the Skills card presets, and unmatched options are omitted. Generate replaces earlier ratings and expertise; a missing profile leaves them blank and shows a note below Generate. After profile application after choosing an archetype, Approaches and Skills each independently have a 20% chance to move one point from a rating of 1 or 2 to another field below 2. Preserve each total, leave expertise in place, and start from the profile on every application. Missing profiles stay blank. Profile application also picks one linked augmentation for the first slot using the existing generator’s Generic names, optional descriptor, purpose text, and manufacturer joined with `·`, clearing the other two slots and all augmentation Glitched marks. No links leaves all three slots blank. Harm, Stress, and Approach Glitched marks keep their values.

- Gear, Extra load, Stress, Harm, and Special Armor use `UiDiamondChoice` for native checkboxes, diamond marks, keyboard focus, and print/forced-color states. Hover uses Gear’s subtle full-row highlight; diamond marks do not use the animated stripe hover. The Stress card keeps the supplied seven-slot connected track and rule text. Selecting a slot checks all earlier slots; clearing a slot clears it and later slots. The final slot highlights overload; Approach glitches remain manually chosen. Stress stays in the character Pinia state and is saved with the sheet.

- The Augmentations card follows the supplied three-line layout and rule text. Each blank text field has an independent Glitched hazard toggle, using the same shared control as Approaches. On desktop, stack Skills, Load/Gear, and Augmentations independently of the Runner/Approaches/Harm/Stress/Resistance column. Keep the existing phone card order. - A compact Runner card sits directly above Approaches in the left desktop column and first on phones. It has two editable fields: Handle and multiline Details and looks. Both use a strong bottom border and a thick yellow left stripe, with closely spaced labels underneath and extra space below the Runner heading. Print uses the same border placement in gray. Angle uses the six supplied choices and the combined rule “Angle // Convey what ultimately you run for:” in a native radio group with diamond marks. It starts unselected, saves with the sheet, is randomly selected from the six choices on each archetype generation, and clears on Reset. Regenerating only Handle or Details and looks preserves the selected angle. Generate and Reset sit at the top right on the same row as Runner. The heading uses the same top and left inset as the other sheet cards. During Reset confirmation, hide Generate and show only really? and nah.; cancelling or completing Reset restores Generate. Above the commit hash, the absolutely positioned shared Guide button uses the same primary yellow appearance as Generate without adding a header row. The sheet state lives in a compressed `character` query, updated automatically with `router.replace` after each Vue update, without a debounce or a history entry per edit. There are no import/export controls; sharing uses the address-bar URL. The versioned format uses a fixed-order compact array, fflate DEFLATE, and base64url. Attribute and skill positions are fixed for version 1, independent of catalogue sorting; gear and expertise labels and archetype IDs remain explicit. A query takes priority over local storage. Opening a link or navigating Back/Forward to another character query validates and loads the sheet; invalid queries show an error and keep existing edits. Without a character query, keep the locally saved sheet and put its state in the URL. Local storage remains the fallback and saves edits as described above. Router updates must not reload their own earlier sheet over newer edits. Name-generator and About links omit character data, and returning through the plain CBR+PNK link keeps the saved edits. Compressed input and decoded output have size bounds; unsupported format versions are rejected. Guide toggles the “File a runner” instructions in a card above all sheet cards, spanning both desktop columns, with shared rules-size text and colored step numbers. Guide expands and collapses over 180ms, with a sharp stepped slide, sideways jumps, and a brief opacity flicker; skip motion when reduced motion is requested. Sheet card headings use the shared ungarble reveal on opening. Skill and approach names replay that text reveal after each archetype generation, including repeated picks of the same archetype; ordinary edits do not replay it. Hide the Guide card when printing. Generate opens the shared category picker without its search field or those instructions; choosing an archetype uses one result from the existing Runners category with Generic, filling the alias and combining real name, role, and appearance in the second field. Generation selects a flavor-available main profession linked to the chosen archetype, or uses the existing catalogue archetype name when none is linked. There is no Archetype dropdown on the card. Closing or cancelling the picker leaves the sheet unchanged. Choosing an archetype also picks one linked augmentation and replaces ratings and expertise from that archetype’s profile; they start blank and are saved with the sheet. Reset sits next to Generate and immediately clears all editable sheet data back to blank defaults and saves the cleared sheet.

- The Load/Gear card sits below Skills on desktop and before Augmentations on phones. Its native segmented load choice is Light [3], Medium [5], or Heavy [7], with Medium preselected. - The Generic CBR+PNK character sheet have a dedicated A4 portrait print layout with 8mm margins. Remove the app header, navigation, dialogs, Generate/Reset, and alerts; retain sheet headings, labels, and rules. Keep two independent desktop columns, with roughly 40% of the available width on the left and 60% on the right: Runner/Augmentations/Harm/Stress/Resistance-Armor on the left, Approaches/Skills/Load-Gear on the right. Arrange the four Approaches in a 2×2 grid when printing to reduce card height. Use “Approaches // Skills” as the combined print heading, hide the Skills heading, and move the expertise rule to the bottom of Approaches. Space print cards 4mm apart both vertically and horizontally, with a tighter 2mm gap between Approaches and Skills under their shared heading. Use four print ink levels: faint writing guides/unselected choices, small light-gray rule text (#aaa), medium-gray structural borders, and black entered text/selected marks. Print gear details at 5pt. Use no outer card borders or dynamic fills, square double-bordered + marks for selected ratings (thin borders and very faint + marks for unselected ratings), double borders for load/glitches, and check marks for expertise, harm, stress, gear, and glitches. Print selected expertise choices first with a border, directly beside the skill block without a fixed-width gap; leave unselected choices very faint for writing over. Printing must remain readable with background graphics disabled. Render current runner, harm, and augmentation text as wrapping print-only values rather than clipped input controls. The phone document order matches its visible and keyboard order. Vue Teleport owns placement in independent desktop and print columns; retain the same card instances and edits when changing layouts, without manually moving Vue elements. Approaches and Skills use separate row components and stable computed references so typing updates only its own row. Use static control-owned hover feedback rather than continuously repainting animated backgrounds. Print layout is independent of the screen width; long user text may require more pages. Other pages have no dedicated print layout.

- Resist/Armor sits directly after Stress, following Harm, on phones and in the left desktop/print column. Keep the supplied resistance rules and roll outcomes static.
