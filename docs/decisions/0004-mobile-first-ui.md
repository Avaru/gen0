# 0004: Interface and routes

Keep the app usable on 320px phones and current browsers. Use a phone single-column layout and a settings/results split when space allows, without horizontal page scrolling.

- Use semantic HTML, visible focus, readable contrast, explicit labels, 44px touch targets, and hidden status announcements. Aim for WCAG 2.2 AA; automated checks do not establish screen-reader or real-device accessibility.
- Shared `Ui*` components own scoped presentation. Central CSS variables own repeated tokens; pages coordinate state with little CSS. Add VueUse only when native HTML, Vue, and Vue Router are insufficient.
- Flavor is a native radio group. Gender and size use checkboxes, all selected initially and always enabled; unchecking the last selected choice selects all the other choices. Each result picks equally among selected choices. Keep each person's name-part gender consistent.
- Categories use a searchable grouped native dialog: full-screen on phones, centered from 640px. Match all search words against category/group labels; Enter selects a single match. Close/Escape cancels, selection closes, and focus returns to the trigger. Focus Close on phones/touch devices and search on larger mouse-driven screens.
- Nationalities appear last, with Mixed first. Generic offers continent mixes; setting flavors offer sovereignty mixes immediately before nationalities. Missing pools remain visible as TODO with coverage notes.
- Generate 10 names initially and on setting changes. Scrolling down to the bottom appends 20 without moving the viewport. The manual button rerolls; no batch-size control or result counters.
- Manual generation reveals the first result only if needed. Category selection, automatic generation, and route restoration do not scroll. Respect reduced motion for scrolling, name reveals, and control transitions.
- Use `/:flavor/:category` and applicable `gender`/`size` queries. Accept comma-separated or repeated query values; discard duplicates/unsupported choices and default empty selections to all. Omit all-selected or irrelevant groups.
- Path settings take precedence over legacy query settings. Normalize root, incomplete, and invalid links with history replacement. Unavailable Known corporations falls back to Corporations; other unavailable categories fall back to Runners. Selection changes add history entries; reload and Back/Forward restore settings and generate fresh results.
- Results are temporary. Details visibility defaults on, survives navigation in app state, and resets on reload. It never regenerates names or enters shared links; remove old `count`/`details` queries.
- About uses `/:flavor/:category/about`, with `/about` also supported. Header links preserve settings and theme; returning generates a fresh batch. Top-menu navigation always scrolls to the top, including selecting the current page. Moving between pages focuses the main content without scrolling or an outline around the text block; initial loads and reloads do not move focus. Settings changes retain control focus. Header focus outlines contrast with the page background, and forced-colors mode exposes native radio/checkbox states. Its heading and text use the shared garbled reveal, respecting reduced motion. Show `v/{short commit hash}` in very small text above the right end of the header's striped separator, using the version supplied during the build.
- Map flavors reactively in `src/styles/themes/index.ts` and bind the theme on `UiShell`. CSS `:has()` applies document tokens. Generic/Shadowrun share yellow, near-black, cyan/coral print styling; CP 2020/77 uses dark red/cyan styling and narrow typography. Layout and controls stay shared; no theme picker or dark/light setting.
- `UiBrandTitle` owns the header title. Generic/Shadowrun's colored layers flicker and shift sideways by up to 96px in stepped bursts starting immediately, for 10 seconds, then stay at their resting offsets. Hovering over the title replays the animation once; remaining hovered does not loop it. The main text stays steady; reduced motion keeps the layers still. `UiCyberpunkTitle` keeps the CP 2020/77 title's separate, static glow.

- Character sheets use `/:flavor/:category/char`, with `/char` also supported. The “char” header link preserves settings and theme. On the sheet, the header caption reads “CBR+PNK / Runner sheet” instead of “Cyberpunk name generator”; there is no duplicate sheet title. `UiCharacterSheet` presents catalogue approaches and skills with editable ratings, expertise, and glitch marks; `UiRatingChecks` provides two native + checkboxes, capped at 2. Selecting the right checks both; clearing the right leaves one, and clearing the left clears both. Approaches and Skills have visible headings and use the name generator’s shared workspace, panel styling, and row typography. Design the sheet against the default theme first; CP 2020/77 adapts the shared layout through existing theme tokens. The small expertise rule sits at the top beside Skills, right-aligned with the expertise inputs. `UiHarmCard` follows the supplied three-level sheet with 2/2/1 independent slots and descriptions stored in Pinia. It sits below Approaches on desktop, after Skills on mobile; a full level 1 turns the card yellow, full level 2 or 3 red, with red taking priority. Pinia owns the sheet, preserving edits across navigation but resetting on reload. Ratings start blank (`null`), expertise empty, and Glitched toggles off. Approach and skill cards use dark/yellow/cyan for 0/1/2, with red overriding only an approach’s color when glitched. The hazard toggle sits next to the rating on desktop, below on smaller screens; a glitched card shows its negative name beside the original, in space reserved even when off, without shifting the layout or changing its rating. Colors reuse the shared palette, with yellow in `--color-rating-one`. Attune is displayed as an optional Weird skill; the form does not perform rules validation, generation, or apply archetype profiles.

- The Stress card uses the supplied seven-slot connected diamond track and rule text, styled with the shared theme. Selecting a slot checks all earlier slots; clearing a slot clears it and later slots. The final slot highlights overload; Approach glitches remain manually chosen. Stress stays in the character Pinia state and resets on reload.

- The Augmentations card follows the supplied three-line layout and rule text. Each blank text field has an independent Glitched hazard toggle, using the same shared control as Approaches. On desktop, stack Augmentations directly below Skills independently of the Approaches/Harm/Stress column. Keep the existing phone card order. Filled augmentation text fields use the yellow skill expertise styling. Entries and marks stay in character Pinia state across navigation and reset on reload.
