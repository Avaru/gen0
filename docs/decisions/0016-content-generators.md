# 0016: Content generators

Compose fictional results from existing human-made fragments. Keep lists editable in `src/data/`, preserve order and duplicate weights, and pass flavor/tag options into every nested generator. Known setting names remain distinct from generated products, places, and company histories.

- **Corporations:** compose names; include employee count and CEO for every size. Minor/AA may have a parent; AAA has none. AA/AAA founding years span 2020–2077. AA has one dated event; AAA has one or two distinct subsidiaries and two or three distinct event types. Events span founding through 2077 and appear chronologically. Subsidiaries request names only, with bounded retries and existing-fragment fallbacks.
- **Company events:** keep user-provided templates and inline `[a|b]` wording choices in `corporation-events.ts`. One row per event type preserves equal type weights; resolve wording choices before name placeholders. Product placeholders use the shared weapon model/series helper, falling back to a type when series is absent. No stock data or graphs. The current year is 2077 for every flavor.
- **Known corporations:** select an existing name in setting flavors, without invented details. Cyberpunk combines the 2020/2077 lists, deduplicated by source URL; keep individual source links. Coverage is a working list, not an exhaustive canon catalogue. See [corporation sources](../data-sources.md).
- **Augmentations:** optional attribute (25%) + type. All types are available in every flavor, with alternate labels where supplied. Details show a manufacturer, preceded by a description only for obscure terms. Kiroshi Optics keeps Kiroshi; other manufacturers use available preferred companies or generated names. Each type has editable `archetypeIds` suitability links to existing catalogue archetypes, inferred from its purpose; see [the complete mapping](../character-data-model.md#random-augmentation-archetype-links). Character archetype application picks one linked type for the first augmentation slot, with the same route flavor naming, optional descriptor, purpose text, and manufacturer as standalone generation, joined into one editable line; standalone augmentation generation keeps the full pool. No game statistics or canon-product claims.
- **Weapons:** manufacturer + composed model/series, with type and optional modifications in details. Omit firearm modifications for melee weapons. Manufacturers follow flavor/exclusions. Company-event products omit manufacturer and modifications.
- **Food menus:** preparation, dish, optional extra, description, and fictional 1–30 prices: credits, Shadowrun ¥, or Cyberpunk €$.
- **Shops:** company/personal owner, optional description, wares, shop type, and appearance/hooks.
- **Device contents:** photos/recordings, credentials, technical files, people, travel records, and maps with internally generated addresses. Display Device data / Commlink data / Shard data by flavor. Shared fragments stay shared; setting terminology uses tags and alternate labels.
- **Cities:** migrated place bases with optional city suffix, population, attribute, and corporate economic fragment. **Streets & plazas:** prefix/ordinal, city or available setting corporation, street type, and optional attribute. Generic falls back to city bases. Populations/descriptions are fictional. Keep device-address composition unchanged.
- **Movies:** title-object-start noun phrases join subjects with “of the”; ending-only phrases stay at the end. `title-prefix-action` selects a stored verb. Suffix chance is 20%. Normalize spaces and preserve phrase casing; position tags do not guarantee every combination is grammatical.
- **Runners:** every result includes general appearance, hair, and clothing in one comma-separated row without section labels. Face shape and one inner trait each appear 75%. Looks use the user-supplied words in `runner-traits.ts` and migrated appearance entries. Face structure (cheekbones/jaw/chin) appears 33%; a face detail, eyes, and a specific garment each appear 50%, independently. Hair always has a style and, unless bald, a color/material descriptor. Clothing always has one condition, one style, and clothes/outfit/style. Mood appears 50% and a day job 20%. Details show `By day: Real name`, followed by `, Job` when rolled; the job is omitted from appearance. Choose entries equally within each available pool; keep profession duplicates. Looks live in their specific pools; there is no outer-trait pool. Shadowrun uses its species/age rules; Generic and Cyberpunk use human age rules without species labels.
- **Gangs, restaurants, bars:** retain migrated composition and details. Venue ratings are fictional.

Migration sources are the neighboring `namegenerator` project's saved cyberpunk BSON lists/patterns and company event templates, plus itemcards.com's Shadowrun lists. Additional augmentation terminology came from the lists discussed with the user. Keep source notices and human-made content; do not invent replacements for excluded setting fragments.
